## Objective

Deliver and maintain the standalone Android application as a mobile host for
the shared Super Chat UI and runtime. Own Android lifecycle, native capabilities,
permissions, storage and recovery, packaging, signing, and device acceptance.
Keep Android APIs behind the Capacitor host boundary.

This task covers Android as a general platform feature. It does not create
separate tasks for individual defects, and it does not claim iOS support.

## Current Baseline — 2026-11-17

- The Capacitor Android shell mounts `SuperChatApp` with `standaloneHost` and
  `StandaloneLLMAdapter`. It includes provider Settings, IndexedDB sessions and
  settings, lifecycle hooks, local calculator/time tools, and Android Keystore
  credential storage.
- The final Android debug build passed and was installed on the OPPO CPH2661IN.
  The first-run Chat and provider Settings screens were visually checked on
  device. No live provider request or credential-save flow was tested.
- The read-only native diagnostics plugin reports Android OS, processor,
  memory, validated network state, transports, and declared app permissions.
  Capacitor plugins add device, battery, app, and network information.
- Debug APK, unsigned release APK, and release AAB builds were verified. The
  matching-runner CI jobs are configured, but remote Actions runs were not
  performed.
- Provider integration, IndexedDB session/settings persistence, lifecycle
  hooks, local tools, and protected credential storage are present in source.
  Provider connectivity, credential saving, persistence across restart,
  interruption recovery, and Android file/document access remain unverified
  or open.

## Standalone integration and device check — 2026-11-17

Commit `f97c608` contains the Android host integration, provider settings,
IndexedDB sessions/settings, lifecycle save hooks, local tools, and the
Keystore-backed credential plugin. `pnpm --filter @super-chat/standalone
build:android:debug` passed, and the APK installed on `.108` (OPPO CPH2661IN).
The first-run Chat route and provider Settings layout were visually checked.
No API key was entered, so provider connectivity and credential storage were
not tested. T32d/e/f remain open for full host behavior, persistence and
recovery acceptance, credential verification, and file/document access;
release signing also remains open.

## Completion Criteria

- The app works on supported Android devices, including lifecycle and
  interruption recovery.
- Sessions and settings survive restart with a documented backup/recovery
  policy; credentials use platform-protected storage.
- Native diagnostics remain read-only and distinguish app-declared permission
  status from permission requests.
- Signed APK/AAB artifacts can be reproduced by the configured build workflow
  and pass the intended distribution checks.
- Device and release acceptance are recorded separately from TypeScript and
  package-build checks. iOS support remains a separate INFRA-1 concern.
