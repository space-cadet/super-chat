## Objective

Deliver and maintain the standalone Android application as a mobile host for
the shared Super Chat UI and runtime. Own Android lifecycle, native capabilities,
permissions, storage and recovery, packaging, signing, and device acceptance.
Keep Android APIs behind the Capacitor host boundary.

This task covers Android as a general platform feature. It does not create
separate tasks for individual defects, and it does not claim iOS support.

## Credential backup handling — 2026-11-17

Android backup rules now exclude the encrypted Keystore credential preferences
from cloud backup and device-to-device transfer on Android 12+, with a legacy
backup exclusion for older versions. The Keystore key is device-local, so
restoring only the encrypted preferences would leave API keys unreadable.
Other eligible app data still follows Android's default backup behavior; the
backup/restore behavior of IndexedDB sessions has not been verified. This
documents and protects credential handling but does not complete T32f's file
and document capability or T32e's recovery acceptance.

## Provider profile and per-chat selection source update — 2026-11-18

The standalone host now exposes saved provider profiles through a non-secret
host capability. The settings screen manages multiple profiles and a default;
each chat can choose its own provider/model, and tab switching restores that
chat's choice. API keys remain profile-specific credential references backed
by Android Keystore. The Android debug build and both TypeScript checks passed.
No device visual check, credential save, live request, or restart/recovery
acceptance was performed for this update; those remain open under T32.

## Completion Criteria

- The app works on supported Android devices, including lifecycle and
  interruption recovery.
- Sessions and settings survive restart with a documented backup/recovery
  policy; credentials use platform-protected storage.
- Native diagnostics remain read-only and distinguish app-declared permission
  status from permission requests.
- Signed APK/AAB artifacts can be reproduced by the configured build workflow
  and pass the intended distribution checks.
- Device and release acceptance are recorded separately from TypeScript and
  package-build checks. iOS support remains a separate INFRA-1 concern.
