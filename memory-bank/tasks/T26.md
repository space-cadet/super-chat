## Objective

Extract obsidian-ai's three-tier memory and pruning behavior into a neutral,
host-backed capability usable by Arxivite, Obsidian, and standalone hosts.

## Subtasks

- [ ] **T26a** — Define the neutral memory-store contract and tier model.
- [ ] **T26b** — Implement short-term, staged, core, and archive memory behavior.
- [ ] **T26c** — Implement memory CRUD, search, audit, restore, and promotion tools.
- [ ] **T26d** — Implement AI pruning, deduplication, and safe recovery.
- [ ] **T26e** — Add host storage adapters and acceptance tests.

## Completion Criteria

- Memory is injected through shared context rules.
- Host storage remains outside shared core.
- Pruning is auditable, reversible, and never silently destructive.
- Arxivite and Obsidian can supply independent memory stores.

## Standalone Memory Implementation — 2026-11-18

Added a shared three-tier memory store and service, CRUD/search tools, activity
review, and snapshot restore. The standalone host persists memory in IndexedDB;
Settings exposes memory controls. Memory injection starts disabled, and new
items remain staged until promoted to core. Shared and standalone typechecks,
the package build, and Android debug build passed. Thirteen copied memory-store
tests passed at an earlier intermediate point; the full suite was not rerun
after final Settings changes. AI pruning/deduplication and a live memory-tool
round trip remain open, as does acceptance for an independent Obsidian store.

## Standalone Sync Selection — 2026-11-19

The standalone WebDAV sync settings can include memory, memory-audit, and
persona data, alongside selected chats and app settings. Credentials are
excluded; usage selection exports session/message counts. This is a sync
adapter integration, not a completion of AI pruning or memory-tool acceptance.
Live WebDAV transfer and recovery remain unverified; see
[`standalone-sync.md`](../implementation-details/standalone-sync.md).
