## Objective

Provide optional shared provider-profile and model-switching behavior for
hosts that need it. This task is not required for Arxivite, which already has
its own provider/model system.

## Subtasks

- [x] **T28a** — Define provider-profile and credential-reference contracts.
- [x] **T28b** — Implement runtime provider/model switching between turns.
- [x] **T28c** — Persist profile selection and provider-neutral model history.
- [x] **T28d** — Add profile-picker UI and active-stream behavior.

## Relationship to Message Context

This task owns selection and switching only when a host chooses to use the
shared feature. It does not change the shared message-context rules or require
Arxivite to move provider/model selection into super-chat.

## Completion Criteria

- Hosts provide profiles and credentials without exposing secrets to sessions.
- Model changes apply without recreating the whole product chat workflow.
- Active-stream switching is cancelled or deferred safely.
- Profile/model state survives reload and passes cross-host tests.

## Standalone provider setup slice — 2026-11-17

Commit `f97c608` adds a standalone UI that stores one provider/model choice and
optional base URL in host settings, then uses `StandaloneLLMAdapter` with the
shared Vercel adapter. API keys are stored through the Android credential
capability; the current standalone host does not expose protected credentials
on desktop or browser. This is a standalone connection path, not the shared
multi-profile picker or per-session fast switching described by T28. The
provider setup screen was visually checked on Android, but no credential save
or live provider request was tested; T28 remains open.

## Profile Switching Implementation — 2026-11-18

- Added the optional `provider-profiles` host capability. Hosts provide a
  non-secret profile list and default profile; API keys continue through the
  credential capability.
- The standalone settings page now supports multiple named profiles, a default
  for new chats, add/edit/duplicate/remove, model suggestions with manual model
  entry, connection checks, and migration from the previous single-provider
  setting.
- Each session stores its selected profile ID, provider, and model. Those
  values are passed to every text or tool-capable request. The chat picker
  changes the active conversation only; switching tabs restores each chat's
  saved selection. The controls are disabled during streaming, and the engine
  rejects changes during an active reply.
- Shared library typecheck, package build, standalone typecheck, and Android
  debug build passed. No tests, live provider request, credential save, or
  device UI check was performed in this implementation pass. Cross-host tests
  and device acceptance remain open, so T28 stays in progress.
