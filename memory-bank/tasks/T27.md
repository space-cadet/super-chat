## Objective

Provide host-agnostic attachment handling for Markdown, PDF, and image inputs,
including model-message conversion, persistence, provenance, and context
budgeting.

## Subtasks

- [ ] **T27a** — Define neutral attachment and document-part types.
- [ ] **T27b** — Implement Markdown and text attachment resolution.
- [ ] **T27c** — Implement PDF attachment resolution and source provenance.
- [ ] **T27d** — Implement image attachment resolution and provider capability checks.
- [ ] **T27e** — Integrate attachments with budgets, persistence, UI, and tests.

## Completion Criteria

- Hosts provide file/document access without leaking platform types.
- Attachments are bounded before provider submission.
- Attachment identity and provenance survive persistence and replay.
- Unsupported media produces a clear, typed result.

## Attachment Implementation — 2026-11-18

Added shared attachment resolution/budget code, attachment composer UI, and
provider message-part conversion, reusing the reference feature source where
it fits. The standalone host now has Android document integration. Shared and
standalone typechecks, the package build, and Android debug build passed; no
full test run followed the final memory/Settings changes. Provider-specific PDF
and image support, file-size/type limits across hosts, and captured-content
replay acceptance remain open.

## Standalone PDF Extraction and Read Tool — 2026-11-19

Added the shared PDF extractor with injected host HTTP and optional PDF.js
client, plus standalone method/server/page settings, a `read_pdf` tool, and
composer PDF-text extraction. Android provides native document access through
its host adapter; browser and desktop use their selected host transports.
Focused PDF and attachment integration checks passed, but live server behavior,
provider-specific PDF/image support, cross-host size/type limits, and persisted
captured-content replay still need acceptance. See
[`attachments-and-context.md`](../implementation-details/attachments-and-context.md).
