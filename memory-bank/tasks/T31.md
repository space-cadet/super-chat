## Objective

Deliver a reliable standalone desktop application that reuses the shared Super
Chat React UI and runtime in an Electron host. Own desktop lifecycle, local
data and credential capabilities, operating-system integration, packaging,
updates, and platform acceptance here. Keep platform APIs behind host/plugin
boundaries instead of adding Electron dependencies to the shared runtime.

This is a platform feature task. Individual bugs and fixes belong in the
relevant implementation or review record, not as separate tasks.

## Current Baseline — 2026-11-17

- `apps/standalone` builds the shared React app for web and Capacitor Electron.
- `apps/standalone/electron/main.ts` starts the Capacitor Electron bridge.
- The desktop diagnostics plugin reports host OS, architecture, processor,
  memory, network reachability, and media-permission status through read-only
  Electron and Node APIs.
- Build scripts and a matching-runner GitHub Actions matrix define macOS,
  Windows, and Linux package targets.
- An Apple Silicon DMG was built and passed `hdiutil verify`.
- `App.tsx` currently mounts `ChatApp` directly; it does not yet use the full
  `SuperChatApp` and neutral host-contract path.
- The chat still uses a local preview model and in-memory persistence. No model
  provider or host-OS tool calling is connected.
- Windows/Linux artifacts and remote Actions runs were not verified in the
  handoff. Signing, updates, durable storage, keychain use, and backup/recovery
  acceptance remain open.

## Standalone integration worktree update — 2026-11-17

The current uncommitted tree routes the shared standalone renderer through
`SuperChatApp` and `standaloneHost`, with IndexedDB session/settings storage,
lifecycle callbacks, local tools, and provider settings. The shared renderer
can be used by the Electron shell, but `standaloneHost` exposes protected API
key storage only on Android. Desktop keychain storage and desktop runtime
acceptance remain open. T31d/e are present in source but have not been verified
as complete; T31f/g remain open.

## Completion Criteria

- The application launches and supports its accepted chat workflow on each
  supported desktop OS.
- Local user data survives restart and has documented recovery behavior;
  credentials are stored through an OS-protected mechanism.
- Desktop permissions and host diagnostics remain read-only unless a separate
  user-approved capability explicitly requires access.
- Supported packages are signed, update behavior is documented and verified,
  and the matching-runner build workflow produces traceable artifacts.
- Acceptance records distinguish local build checks, CI artifacts, and manual
  platform checks.
