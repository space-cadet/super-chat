## Objective

Make RAG a real shared chat workflow: `super-chat` owns retrieval
orchestration, context budgeting, progress, citations, provenance, and replay;
each host owns its data source, retrieval algorithm, and domain ranking.

Do not port Arxivite's domain-specific RAG implementation into `super-chat`.
Keep it in Arxivite behind `RetrievalCapability`.

## Shared Flow

```text
user turn
  -> shared retrieval decision
  -> host retrieval capability
  -> normalized sources with stable IDs and provenance
  -> shared budgeting and prompt assembly
  -> shared progress/citation events
  -> persisted record for replay
```

domain RAG system or create a large manager class.

Highest-priority current gap: retrieval happens before the engine creates its
abort controller, marks the turn active, and persists the initial user turn.
This can allow an uncancellable slow host request, a concurrent send, or an
unpersisted retrieval failure.

## 2026-09-01 Lifecycle Slice

Implemented the first Phase 5 hardening slice in the shared engine:

- The engine establishes its active-turn lock and abort controller before host
  retrieval starts.
- The user message and streaming turn are persisted before retrieval, so a
  reload cannot lose a query while a host search is pending.
- `SendOptions.signal` now cancels the engine-owned turn, and slow retrieval is
  raced against cancellation so the stream can finish even if a host promise
  does not settle promptly.
- Host-backed retrieval receives the active abort signal through
  `HostRAGAdapter` and `HostOperationContext`.
- Retrieval emits shared `rag-status` events, persists successful retrieval
  state, and records failed or cancelled pre-provider turns durably.
- Added focused coverage for the slow-retrieval lock/cancellation path and
  retrieval failure without provider execution.

## 2026-09-01 Context Slice

Added `src/core/retrieval.ts` as a small pure retrieval/context module. It
validates required source and provenance fields, deduplicates by capability and
source identity, orders results deterministically by score, applies optional
result limits, and keeps formatted evidence within the configured context
token budget. Evidence is explicitly delimited as untrusted reference
material.

`ChatEngine` now persists the bounded source list and assembled context on the
turn and uses that assembled context in the provider prompt. The public core
exports the helper types and functions, and `HostRAGAdapter` passes
`maxRetrievalResults` through to the host capability.

## 2026-09-01 Replay Slice

Added explicit latest-turn replay behavior to `ChatEngine`. `replayTurn` and
`replayMessage` append a new durable turn from the saved user message, reuse
the saved bounded retrieval context by default, and keep the original turn
and evidence intact for auditability. Callers can pass `refreshRetrieval` to
run host retrieval again. Older turns are rejected until branching semantics
are defined, so replay cannot silently mix later conversation history with an
earlier turn.

Retrieval status, warnings, and typed errors are now durable turn fields and
are restored with source/provenance validation. The React retry action now
uses the shared replay API instead of a placeholder callback.
