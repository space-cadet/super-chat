## Objective

Make RAG a real shared chat workflow: `super-chat` owns retrieval
orchestration, context budgeting, progress, citations, provenance, and replay;
each host owns its data source, retrieval algorithm, and domain ranking.

Do not port Arxivite's domain-specific RAG implementation into `super-chat`.
Keep it in Arxivite behind `RetrievalCapability`.

## Shared Flow

```text
user turn
  -> shared retrieval decision
  -> host retrieval capability
  -> normalized sources with stable IDs and provenance
  -> shared budgeting and prompt assembly
  -> shared progress/citation events
  -> persisted record for replay
```

## 2026-09-01 Plan Verification

The Sol-medium read-only review confirmed that Phase 4 already provides a thin
host-backed retrieval path. Phase 5 should harden that path rather than port a
domain RAG system or create a large manager class.

Highest-priority current gap: retrieval happens before the engine creates its
abort controller, marks the turn active, and persists the initial user turn.
This can allow an uncancellable slow host request, a concurrent send, or an
unpersisted retrieval failure.

Recommended implementation order:

1. Settle one neutral retrieval contract and compatibility treatment for the
   legacy paper methods.
2. Move retrieval into the protected ChatEngine lifecycle and normalize
   cancellation, authorization, partial, invalid, and unavailable outcomes.
3. Add a small pure retrieval/context module for validation, budgeting,
   evidence formatting, and source selection.
4. Harden persistence and replay, including safe migration of Phase 4 records.
5. Wire a real retrieval setting and progress/error/source state into React.
6. Run fixture and Arxivite retrieval conformance tests.

Keep `AgentLoop`, persistence adapters, Arxivite's PocketFlow/ranking, and
Obsidian search outside this Phase 5 core slice unless a focused acceptance
test proves a compatibility need.

Review evidence: the temporary read-only worktree matched `42c3b75`; TypeScript
passed; the full-suite run showed 121/122 because `SuperChatApp.test.tsx`
timed out under parallel load, while that test passed independently. Stabilize
that timing-sensitive test before using an all-green suite as the Phase 5 gate.

storage, paper filtering, ranking, and anti-hallucination domain prompts where
appropriate. It returns normalized results; it does not own the chat event
loop or citation UI.
