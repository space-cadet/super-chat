## Objective

Use `obsidian-ai` as the behavioral reference for mature capabilities that
belong in the shared chat application. Extract reusable mechanisms into
`super-chat` while leaving vault, editor, workspace, plugin, sync, updater,
and other Obsidian-specific behavior behind host capability interfaces.

This is not a wholesale source port.

## Authoritative Plan

Follow
[`implementation-details/embeddable-super-chat-platform.md`](../implementation-details/embeddable-super-chat-platform.md),
especially sections 3, 4, 5, and 8.

## Candidate Capability Groups

1. Provider/model profiles, switching, and diagnostics.
2. Session tabs, drafts, saved-session search, and replay.
3. Agent loops, retries, cancellation, reasoning, and error handling.
4. Multi-agent routing, mentions, participant identities, and context policy.
5. Tool registry/descriptors, approval, audit, and result presentation.
6. Model-ready history, tool pairing, context budget, and compaction.
7. Provider usage, local estimates, and token/cost presentation.
8. Persistent memory and explicit past-session retrieval.
9. Markdown, LaTeX, citations, message actions, and context presentation.

## Extraction Procedure for Every Slice

1. Reconcile the current `obsidian-ai` Memory Bank with source and tests.
2. Trace all call sites and separate reusable behavior from platform behavior.
3. Add characterization tests around existing user-visible and safety behavior.
4. Define the smallest neutral contract needed by the slice.
5. Implement the reusable mechanism in `super-chat`.
6. Implement or adjust the Obsidian host side without changing behavior.
7. Run shared unit/contract tests and affected Obsidian tests.
8. Perform manual Obsidian acceptance for vault/editor/workspace behavior.
9. Remove old code only after parity and rollback evidence exist.

## First Slice

Do not start broad extraction until T22's fixture-host safety slice is green.
Then use one read-only Obsidian tool and one approval-required write tool to
prove the shared descriptor, policy, approval, execution, audit, persistence,
and UI path.
