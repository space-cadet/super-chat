## Objective

Use `obsidian-ai` as the behavioral reference for the mature agentic runtime
and priority capabilities that belong in the shared chat application. Extract
reusable mechanisms into `super-chat` while leaving vault, editor, workspace,
plugin, sync, updater, and other Obsidian-specific behavior behind host
capability interfaces.

This is not a wholesale source port.

## Candidate Capability Groups

1. Agent loops, retries, cancellation, reasoning, and error handling.
2. Tool registry/providers, approval, audit, and result presentation.
3. Model-ready history, tool pairing, context budget, compaction, and replay.
4. Three-tier memory, AI pruning, and explicit past-session retrieval.
5. PDF, image, and Markdown attachments.
6. Provider profiles, fast model switching, diagnostics, and export/import.

## Extraction Procedure for Every Slice

1. Reconcile the current `obsidian-ai` Memory Bank with source and tests.
2. Trace all call sites and separate reusable behavior from platform behavior.
3. Add characterization tests around existing user-visible and safety behavior.
4. Define the smallest neutral contract needed by the slice.
5. Implement the reusable mechanism in `super-chat`.
6. Implement or adjust the Obsidian host side without changing behavior.
7. Run shared unit/contract tests and affected Obsidian tests.
8. Perform manual Obsidian acceptance for vault/editor/workspace behavior.
9. Remove old code only after parity and rollback evidence exist.

## First Slice

Do not start broad extraction until T22's fixture-host safety slice is green.
Then use one read-only Obsidian tool and one approval-required write tool to
prove the shared descriptor, policy, approval, execution, audit, persistence,
and UI path.
