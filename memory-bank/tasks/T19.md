# T19: Make Arxivite a super-chat Host Harness

*Created: 2026-06-20 00:10:00 IST*
*Last Updated: 2026-09-06 13:13:22 IST*

**Status**: ⬜ **PENDING**
**Priority**: HIGH
**Phase**: Phase 4 — Host Migration
**Parent**: T22

## Objective

Replace Arxivite-owned chat mechanics with the complete `SuperChatApp`.
Arxivite becomes a pluggable host/tool provider exposed through
`ArxiviteSuperChatHost`.

The final page should conceptually do only this:

```tsx
const host = useArxiviteSuperChatHost();
return <SuperChatApp host={host} />;
```

## Arxivite Responsibilities

- Authenticated identity and authorization.
- Papers, bookmarks, collections, notes, and reading history.
- Supabase-backed physical persistence.
- Paper/PDF search and fetch tools, structured evidence, and source metadata.
- Arxivite-specific tools, risk metadata, and authorization.
- Navigation to papers and product screens.
- Product-specific credential/provider policy where required.

## Mechanics Arxivite Must Not Own in the Final Path

- Response streaming and assistant-text accumulation.
- Tool-call, approval, and tool-result workflow.
- Parallel chat session synchronization.
- Separate user/assistant save orchestration around the engine.
- Shared message, citation, tool, session, or settings UI.
- Retry, cancellation, model-history, or context-budget behavior.

## Migration Plan

1. Pin a known compatible version/artifact of `super-chat`.
2. Implement `ArxiviteSuperChatHost` using existing adapters where sound.
3. Establish typed session identity and exactly one persistence write owner.
4. Connect Arxivite paper/PDF tools through the T16 agentic RAG contract.
5. Mount `SuperChatApp` behind the existing feature toggle.
6. Test streaming, reload, session switching, tools, approval, RAG, citations,
   cancellation, failures, auth changes, and responsive layouts.
7. Make the host path default only after acceptance.
8. Remove legacy mechanics in a separate reversible change.
