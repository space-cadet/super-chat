## Objective

The longer-term goal is conversations among people and AI. The current app is
for one person using one Android device with local data. Remote authentication,
networked users and a hosted backend are not part of the current implementation.
Neon + Clerk were discussed but not selected or provisioned.

Design: [accounts and collaboration](../implementation-details/accounts-and-collaboration.md). T22 owns generic conversation behavior and messaging contracts;
T33 owns the standalone account/backend implementation and permissions. Obsidian
continues to provide its own host identity and vault storage.

## Subtasks

- [ ] **T33a** — Define the global ownership model, local identity/storage context and permission rules first. Evaluate Neon + Clerk and message delivery later.
- [ ] **T33b** — First implement one persistent local user and local login/sign-out without remote authentication, then add remote sign-in/linking later. Define recovery and restart policy explicitly.
- [ ] **T33c** — Scope chats, drafts, tabs, settings, memory, profiles, credentials, sync state and caches to the current account; stop old work and clear in-memory state on switching.
- [ ] **T33d** — Define and implement recoverable migration of existing local chats into an account, with explicit user choice before upload.
- [ ] **T33e** — Implement conversation creation, membership, invitations, roles, access removal and authenticated backend operations with T22 messaging.
- [ ] **T33f** — Define and implement account export/deletion and shared-conversation retention/ownership rules with T30.
- [ ] **T33g** — Verify account isolation, switching, expiry, unauthorized access and two-client human/AI delivery and recovery with the feature/platform owners.

## Acceptance

- [ ] Identity is established before loading account data; another account cannot read or modify it.
- [ ] Sender identity and conversation permissions are verified by the backend.
- [ ] Sign-out/switch cancels active turns and subscriptions; delayed writes cannot reach the next account.
- [ ] Existing local data has an explicit, recoverable migration path.
- [ ] Two users see the same authorized human and AI messages after reconnect, without duplicate model execution.
- [ ] Private memory, provider secrets and local tools are not implicitly shared.
- [ ] Web, Android and desktop authentication have separate runtime evidence.
